# Designer contract decisions

Updated 2026-10-23 (America/Phoenix). The user authorized the full refresh, superseding the earlier per-stage approval checkpoints, and later supplied a registry token for real-data testing.

- Export compatibility target: `causalbench-asu==0.2.5`, based on the supplied documentation. YAML records `major: '0'`, `minor: '2'`, `build: '5'`. Registry component versions remain separate identities.
- Sources: supplied `cb-docs/docs/contexts.md`, `modules/tasks.md`, `modules/datasets.md`, `modules/models-metrics.md`, and `api.md`. The supplemental packages target different tasks and are preserved intact.
- Authenticated POST fetches for tasks, datasets, models, and metrics were verified on 2026-10-23 with the user-supplied token. Observed keys are `task_descriptors`, `dataset_descriptors`, `modl_descriptors`, and `metric_descriptors`, inside `data` alongside `total_count`, `page_number`, and `page_size`. The initial unauthenticated probe's HTTP 401 envelope remains historical evidence. Tokens are never included in source, fixture files, or context exports.
- The live model/metric fetch schemas return HTTP 422 without `user_id`; supplying the current JWT's numeric `sub` resolves that requirement. It is an unverified client request hint, never an authorization decision; the bearer token remains server-authenticated. Missing/non-numeric subjects fail visibly for these two catalogs. Tasks/datasets do not receive a user ID hint. No identity is hardcoded.
- Registry adapters accept the observed version-list envelopes, retain missing metadata as unknown, and fail visibly on unsupported responses. Dataset/model/metric fetches sort by **Uploaded Date descending**. Stable dataset pagination was checked as 1,000 + 472 + 0 module descriptors with 1,472 distinct IDs; unsorted pagination was unreliable. Repeated/overlapping pages and bounded-request exhaustion fail explicitly instead of returning a partial catalog.
- Task methods cannot be reconstructed from a task YAML or task name. The browser never executes contributed Python. Until a supported backend descriptor is available, an explicit, user-supplied JSON descriptor supplies the three task input maps, exact component task references, dataset aliases/formats, and parameter declarations. It is metadata authoring, not context import. Its provenance is shown and its accuracy remains the user's responsibility.
- The observed live catalogs do not supply complete input contracts, dataset alias manifests, or exact model/metric task versions. The Sachs example's missing fields were read from downloaded, inspected packages: task 1 v1, dataset 1443 v1, model 3 v1, metric 1 v1. Its exact designer-generated Python executed locally against those archives with networking disabled; YAML overrides plus manifest defaults matched the effective recipe. One scenario/evaluation returned graph accuracy 0.7768595041322314. This establishes a functional smoke test, not scientific suitability; nothing was published.
- Only explicit `files` alias maps are treated as dataset aliases. Legacy feature filenames/file types are insufficient evidence and are not converted into aliases automatically.
- `dataframe` maps to `SpatioTemporalData`; both graph formats map to `SpatioTemporalGraph`. Static and temporal distinctions are retained. Runtime types outside these two classes remain unknown in browser checks.
- Missing contract evidence blocks validated export. Runtime model output keys/types, actual dataset contents, helper behavior, and scientific suitability remain Python checks even when metadata checks pass.
- Context YAML contains direct overrides; no declaration wrappers, local entry IDs, labels, or canvas presentation data. Explicit parameter sets expand into separate model/metric entries. A range string is a string, not an expanded search.
- Context has a local **Show task composition** switch: cards and automatic task wiring are two presentations of the same draft. The experimental Blueprint route restores editable canvas positions, generic sketch connections, and processor design notes in a separate root store. Configured component nodes reference shared draft entries and use the same editor/validation/export. Sketches and processors do not execute or serialize; unconfigured component nodes block blueprint export. Task-aware executable connections are a planned revision, not current behavior. Navigation preserves draft and presentation state in memory; automatic reload persistence remains deferred.
- **Open context** reads an exact saved registry version, local YAML/JSON, a context ZIP, or pasted YAML/JSON. Selection produces a preview; only explicit Open/Replace changes the draft. Errors and cancellation preserve existing work. Replacement resets the old canvas layout, sketches, selection, and viewport, then creates nodes for restored recipe entries. Source identity is displayed separately and is not serialized into the recipe. Edits remain local; no registry write/publication endpoint is called.
- Saved-context registry contracts were checked against the public OpenAPI schema and current website adapter, then verified in connected Chrome. `POST /pipelines/fetch` uses the current JWT's numeric subject as `user_id`, `Creation Time` descending, empty search/filters/versionFilters, page size 1,000, and `showOnlyUserData: false`. The version envelope is `data.pipelines[].pipeline_version_info[]` with `pipeline_id`, `pipeline_version`, `pipeline_name`, and `pipeline_description`. `GET /pipelines/download/{id}/{version}` supplies the context ZIP with bearer authentication. Pagination continues to empty and rejects overlap/limits; session changes cancel outstanding work. No account identity is hardcoded.
- Imports accept CB 0.2.x with exact positive integer component identities and finite JSON override values. Defaults may be omitted; unknown fields, aliases, duplicate YAML keys, unsupported structures, and incompatible versions fail before replacement. Configurations are limited to 2 MB, archives to 8 MB, entries to 10,000, and override nesting to 40 levels. Lazy `yaml@2.9.1` and `fflate@0.8.2` read only the single `config.yaml`/`config.yml`/`config.json` in an archive; Python and other archive files are never executed or extracted to disk.
- Import preserves exact references, mappings, typed overrides, duplicates, and serialized order. Only consecutive model/metric entries sharing ID/version are grouped into one editor entry with explicit configurations. Missing descriptors become labeled reference metadata, never guessed contracts. Saved unresolved mappings and overrides stay editable, but unknown required metadata blocks validated export. Later exact catalog descriptors fill missing metadata without overwriting mappings or overrides; applying an already-open editor retains that updated metadata. Manually supplied metadata takes priority.
- Light/dark appearance uses shared semantic CSS variables across the shell, forms, dialogs, and SVG canvas. The initial appearance follows the system; explicit choices persist in local storage when available, independently of recipes and session tokens.

Fixtures under `tests/fixtures/` are synthetic documentation-derived examples with fictitious IDs. They are not registry availability claims or modifications of supplied examples.
